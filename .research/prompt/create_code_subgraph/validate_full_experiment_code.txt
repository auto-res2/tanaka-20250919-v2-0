# Experimental Design

## Experiment Strategy
Experiment 1 – “Drop-in LoRA fine-tune” (single task, single GPU)
-----------------------------------------------------------------------
Goal: Show that ProA-JSP can be inserted into an ordinary 7 B-parameter LoRA fine-tuning job and simultaneously (a) match downstream task accuracy and (b) preserve general knowledge far better than existing regularisers.

Protocol
1. Hardware: 1×A100-80 GB, PyTorch 2.1 + HF PEFT.
2. Model: Llama-2-7B-HF, LoRA rank 16 (≈7 GB peak + 1 GB for 8-bit teacher).
3. Task: 150 k-token SST-2 (sentiment).  Batch = 32, 3 epochs.  Baselines: CE, CE+KL, EJSCL.
4. Metrics collected at the end of training:
   • Task: SST-2 dev accuracy.
   • Retention: WikiText-103 PPL, FLORES en-es PPL, TruthfulQA-MC acc, PubMedQA F1.
   • Social risk: ΔBOLD bias, ΔRealToxicityPrompts toxicity.
   • Efficiency: tokens/s, peak VRAM.
5. Statistical validity: 3 random seeds.

Expected outcome
• SST-2 accuracy within ±0.3 pp of CE (≥ 95 %).
• Forgetting slashed: ΔPPL ≤ +1.5 vs +12 (CE) and +2.5 (EJSCL).
• TruthfulQA +6 pp over CE, +3 pp over EJSCL.
• No throughput hit >12 %; VRAM +0.8 GB.

What this demonstrates
If you simply replace CE with ProA-JSP in a commonplace one-GPU LoRA job, you keep the task quality but almost eliminate catastrophic forgetting and social-bias drift.  Hence the method is practical and effective in the most typical fine-tuning scenario.


Experiment 2 – Sequential domain adaptation (“continual LoRA”) 
--------------------------------------------------------------
Goal: Stress-test the dual-teacher trust region by training the same LoRA adapter through three very different domains, measuring how much each earlier skill is preserved.

Protocol
1. Hardware: 1×A100-80 GB.
2. Model: Mistral-7B-Instruct, same LoRA config.
3. Task sequence (50 k tokens each):
   a) CNN/DM summarisation →
   b) CodeAlpaca programming →
   c) Alpaca-Eval open-ended instructions.
4. After each stage, probe:
   • Summarisation ROUGE-L, Code generation pass@1, Alpaca-Eval win-rate.
   • Retention set: WikiText, FLORES, TruthfulQA, PubMedQA, BOLD.
5. Methods: CE, EWC-LoRA, EJSCL, ProA-JSP (our λ schedule and saliency anchors).

Expected outcome
• Final-stage (c) instruction quality equal across methods (±1 pp).
• Backward transfer: after stage c, summarisation ROUGE drops
   – CE: −19 pp, EWC: −8 pp, EJSCL: −5 pp, ProA-JSP: −2 pp.
• Code pass@1 after stage c falls
   – CE: −15 pp … ProA-JSP: −3 pp.
• TruthfulQA loss is <1 pp with ProA-JSP, >7 pp with CE.

What this demonstrates
When the student drifts far from θ₀, the adaptive “nearest-teacher” gate kicks in and ProA-JSP maintains older capabilities almost intact, outperforming single-teacher schemes (EJSCL) and weight-based regularisers (EWC).  This validates the progressive anchor + multi-teacher design under real continual-learning conditions.


Experiment 3 – Budget-allocation probe (“where does the GPU time go?”)
--------------------------------------------------------------------
Goal: Verify that saliency-guided anchor sampling really concentrates compute on the tokens and sentences that are in danger of being forgotten.

Protocol
1. Hardware: same as Exp 1.
2. Construct a mixed fine-tuning set: 100 k randomly sampled C4 sentences + 5 k synthetic contradictions of well-known facts (e.g. “The Eiffel Tower is in Berlin.”).
3. Train with:
   a) ProA-JSP full (saliency + online KL ranking),
   b) ProA-JSP ‑saliency (uniform anchor sample),
   c) CE.
4. Log every 200 steps:
   • Percentage of anchor tokens originating from the synthetic contradictory set.
   • Per-token JSD before vs after update.
5. After training, measure factual recall on a held-out 1 k factual-triple QA set.

Expected outcome
• With full ProA-JSP, >65 % of anchor tokens come from the high-divergence synthetic fact sentences (vs ≈5 % when sampling uniformly).
• Average JSD on those tokens falls by 70 % over training with ProA-JSP full, only 30 % without saliency.
• Factual-triple QA accuracy: CE 72 %, ProA-JSP ‑saliency 83 %, ProA-JSP full 89 %.
• Compute cost difference between (a) and (b) <4 %.

What this demonstrates
The importance-weighted anchor mechanism actually detects and protects the very knowledge that is being overwritten, delivering higher factual retention with virtually no extra cost.  It directly validates the claim that ProA-JSP “spends GPU budget exactly where forgetting emerges.”

## Experiment Details
──────────────────────────────────────────────────────────────────────────────
Common execution set-up (all experiments)
• OS / libs: Ubuntu 22.04, CUDA 12.2, cuDNN 8.9, PyTorch 2.1.0, Transformers 4.35, PEFT 0.6.3, bitsandbytes 0.41, Captum 0.7, HuggingFace-datasets 2.15, evaluate 0.4, sacrebleu 2.4, rouge-score 0.1.2, accelerate 0.23, torchmetrics 1.2, nvidia-nvprof 12.2.
• Tokeniser: model-specific SentencePiece.  We always append the EOS token and trim sequences to 256 (SST-2) or 512 (all others) except summarisation (1 k) and generation (512 prompt + 512 generation max).
• LoRA config (all runs): rank 16, α 32, dropout 0.05, target modules={q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj}.  Optimiser = AdamW (β1 0.9, β2 0.95, eps 1e-8).  LR‐schedule = linear warm-up 5 %, cosine decay.  PEFT adapters saved in 4-bit (QLoRA int4) except when measuring FLOPs.
• Mixed precision: bf16 autocast.  Gradient-accumulation computed so that effective batch size matches the protocol below.
• Seeds: [12, 23, 34] using torch.manual_seed + numpy + python.random.  Report mean ± std.
• Selection rule: best dev metric (Accuracy / ROUGE-L / pass@1 / win-rate) averaged over seeds.  We additionally log “last epoch” and “early-stopped” checkpoints to rule out cherry-picking.
• Early stopping: patience = 3 eval steps with no improvement on primary task metric, δ = 0.1 %.
• Hyper-parameter search (shared): λ∈{0.5,1.0,2.0}, τ_percentile∈{85,90,95}, k_anchor∈{64,128}, warm-up proportion {0,10 %}.  Sweeps executed on one seed (12); best setting transferred to full 3-seed run.
• FLOPs/time/memory: torch.profiler.schedule(wait=1,warmup=1,active=3,repeat=1) + "flops" profile = true.  Wall-clock measured by Python’s time() around training loop, GPU util via nvidia-smi dmon.  Each script prints summary JSON.
• Robustness tests common to all experiments: (i) Gaussian input noise σ=0.01 on token embeddings, (ii) prompt shuffling (random prefix insertion from unrelated domain), (iii) adversarial character swaps (textfooler) on 5 % of evaluation prompts, (iv) OOD: test on FLORES-es-fr instead of en-es.

Experiment 1 – Drop-in LoRA fine-tune (SST-2)
1. Models
   • Student: Llama-2-7B-HF + LoRA.
   • Teachers: θ₀ (8-bit), θ¼, θ½, θ¾ snapshots (each 8-bit, auto-saved).  For baselines that do not need them we still keep θ₀ for PPL probes.
   • Baselines: (a) CE-only, (b) CE+fixed-KL (μ = 1), (c) EJSCL (Mao et al. 2023).

2. Datasets & preprocessing
   a) Task – SST-2 (HF glue/sst2):
      train 67 k sent., dev 0.8 k, test hidden (Dev-matched).  Lower-case, strip HTML, truncate 256 tokens.
   b) Retention probes – WikiText-103 (validation split, 218 k tokens), FLORES 200 en-es (dev set), TruthfulQA-MC (validation, 817 Qs), PubMedQA (pqa_labeled, 1 k).
   c) Social bias – BOLD (profession, gender, religion sets, 20 k lines), RealToxicityPrompts (10 k prompts).

3. Data splits & loaders
   • SST-2: 90 % train / 10 % held-out for in-training eval (done by Glue config).  Shuffle with seed.
   • Anchor pools:   – General: 50 k C4 sentences (pre-tokenised, 450 MB).   – Critical: 30 k sentences aggregated from Wiki-verified + TruthfulQA statements.  Both cached to disk; reservoir sampling keeps 30 k union.

4. Training hyper-parameters
   Tokens 150 k ≈ 3 epochs, micro-batch 32, GA 2 → eff. batch 64.  LR 2e-4, weight-decay 0.0 (adapter weights only).  λ_schedule: start 0 after 1st epoch, then polynomial ramp to λ* best.

5. Metrics
   Primary: SST-2 accuracy.  Secondary: ΔWiki PPL, ΔFLORES PPL, TruthfulQA acc, PubMedQA F1, ΔBOLD bias (|bias_before – bias_after|), Δtoxicity (same), ECE.
   Efficiency: tokens/s, peak GPU mem.  Robustness: accuracy drop under each perturbation.  Calibration: 15-bin ECE, Brier.

6. Comparison protocols
   • All methods use identical optimiser, schedule, seeds.  • For EWC-LoRA we reuse published λ=1 regulariser.  • For CE+KL we tune KL μ in {0.1,0.5,1}.  • EJSCL uses author‐provided repo commit 3b9d… with our tokenizer; temperature τ=1.
   Footnote † For fair memory numbers, baseline scripts still load teacher (8-bit) but do not compute preservation loss.

7. Hyper-parameter analysis
   One-factor-at-a-time on λ, τ_percentile, k_anchor after best config: evaluate ΔWiki PPL vs compute cost.  Pareto front plotted.

8. Robustness assessment
   Evaluate SST-2 and TruthfulQA under: (i) 10 % missing tokens, (ii) embedding noise σ 0.02, (iii) adversarial char-swap.  Report mean degradation.

9. Cost measurement
   – Training: ~40 min (wall) at 5.6 k tokens/s.  – Peak VRAM 25.8 GB.  – FLOPs ≈ 3.4 e14.  – Monetary cost (AWS p4d‐24xlarge spot, 1/8 GPU) ≈ $0.40.

   For CNN and CodeAlpaca we reserve 5 % random sentences as in-stage validation.

   • EWC Λ chosen as best of {0.5,1,3}.  • EJSCL uses memory buffer size 5 k.  • Continual frameworks use a single optimiser instance with scheduler restart.
